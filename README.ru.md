# Agent Workspace Inspector

Универсальный skill для инспекции и улучшения рабочего пространства **OpenAI Codex** или **Claude Code**. Он сравнивает реально работающую конфигурацию с harness из этого репозитория и обосновывает, что подходит лучше: оставить как есть, внести точечные изменения, объединить выбранные части или заменить соответствующую часть настроек. Наш шаблон — кандидат для сравнения, а не замена по умолчанию.

Он проверяет реально загружаемые инструкции, skills, subagents, MCP, hooks, область действия настроек, маршрутизацию, handoff, checkpoints, верификацию и необязательную телеметрию. Существенные рекомендации связывает с документацией платформы, исследованиями и данными конкретного рабочего пространства, отделяя их от инженерных предположений. Полезные текущие требования сохраняются при адаптации или замене.

## Установка в Codex

Попросите Codex установить skill из:

```text
https://github.com/antuzinski/agent-workspace-inspector/tree/main/workspace-inspector
```

Либо скопируйте папку `workspace-inspector/` в:

```text
~/.codex/skills/workspace-inspector/
<repo>/.agents/skills/workspace-inspector/
```

Запуск:

```text
$workspace-inspector Сравни это рабочее пространство с harness из данного GitHub-репозитория. Сопоставь варианты оставить, точечно изменить, объединить и заменить; обоснуй выбор источниками и границами их применимости. Примени подходящие обратимые изменения, включая полную замену, только если она действительно лучше подходит, и сохрани мои требования.
```

## Установка в Claude Code

Скопируйте папку `workspace-inspector/` в:

```text
~/.claude/skills/workspace-inspector/
<repo>/.claude/skills/workspace-inspector/
```

Запуск:

```text
/workspace-inspector проведи аудит этого рабочего пространства Claude Code
```

Общий `SKILL.md` совместим с обеими системами. Готовые шаблоны разделены на `assets/codex/` и `assets/claude/`.

## Что настраивается

- основная работа выполняется текущим агентом;
- bounded worker получает только самостоятельную и проверяемую часть;
- critical reviewer используется только при существенном риске или неразрешённой проблеме;
- subagents всегда возвращают результат основному агенту;
- checkpoint создаётся только на реальной границе зависимости, риска, паузы или делегирования;
- результат подтверждается пропорциональной проверкой.

## Как выбирается изменение

1. Проверяется, что реально активно в рабочем пространстве, а не просто сохранено в файлах.
2. Фиксируются цель пользователя, ограничения и уже работающие механизмы, которые нужно сохранить.
3. На одинаковых критериях сравниваются варианты: оставить текущую систему, внести точечные изменения, объединить выбранные части harness или заменить им соответствующую часть настроек.
4. Рекомендация объясняет главный альтернативный вариант, критерий выбора, источники и их ограничения, риски, план сохранения требований и способ проверки. Для существенных утверждений по исследованиям и документации приводятся ссылки; неподтверждённые причинные объяснения помечаются как предположения.
5. Изменения применяются в пределах разрешённого запроса. Условная просьба «примени лучший вариант» или «замени мои настройки этим harness, если он подходит» разрешает выбрать путь и внести обратимые изменения в его пределах, включая полную замену, когда она обоснована. Повторно спрашивать то же разрешение не нужно. Уточнение требуется только при существенной неразрешённой развилке или неавторизованном необратимом/внешнем действии.

Краткое основание и ограничения исследований приведены в [`workspace-inspector/references/evidence-basis.md`](workspace-inspector/references/evidence-basis.md). Документация подтверждает доступность механизмов, но сама по себе не доказывает рост качества, снижение стоимости или ускорение.

Названия моделей не зафиксированы жёстко: доступность и оптимальный выбор зависят от продукта, тарифа и текущей версии.
